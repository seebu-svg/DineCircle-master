Three sibling screen packages with no shared sub-logic:
- `host/` — `HostDashboardScreen` is a `ConsumerStatefulWidget` using Riverpod (`flutter_riverpod`) to watch `myEventsProvider`, `myHostSummaryProvider`, `myHostPayoutsProvider`, `currentUserProvider`, partner/invite providers; it owns a `TabController` driving Overview / Events / Earnings / Collabs via `TabBarView`. Navigation to child screens (`EventManageScreen`, `AnalyticsScreen`, `CreateDinnerScreen`) goes through `Navigator.push` with `MaterialPageRoute`. Draft lifecycle (edit/publish/delete) calls `eventsControllerProvider.patchEvent` / `cancelEvent`; withdrawals call `walletControllerProvider.withdraw`; invite accept/decline call `invitesControllerProvider`. All API errors are caught as `ApiException` and surfaced via `ScaffoldMessenger.showSnackBar`.
- `tables/` — `MyTablesScreen` is a plain `StatefulWidget` tabbed into Upcoming/Past, rendering `Booking` cards from `MockData.bookings` (no provider wiring yet).
- `offers/` — `OffersScreen` uses a `DefaultTabController` to filter `MockData.partnerOffers` by `OfferType.discount` vs `exclusiveExperience`.
Dependency direction: screens depend on `../../models/*`, `../../providers/*`, `../../widgets/*`, and `../../theme/*`; they do not import each other except `host_dashboard_screen.dart` importing its siblings `analytics_screen.dart` and `event_manage_screen.dart`.
