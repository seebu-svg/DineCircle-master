- Screens consume data through Riverpod's `ConsumerStatefulWidget` / `ref.watch(ref)` pattern rather than passing state down, keeping screens read-only consumers of providers like `myBookingsProvider` and `bookingsControllerProvider`.
- All layout spacing, radii, and typography come from the shared `AppSpacing`, `AppColors`, and `AppTextStyles` modules instead of hard-coded values, ensuring consistent design tokens across checkout, bookings, and confirmation screens.
- Overflow-safe text uses `Flexible` / `Expanded` inside `Row`s combined with `maxLines: 1` and `overflow: TextOverflow.ellipsis` on every label/value pair (detail rows, recap rows, chips, pass headers).
- Long-running async operations wrap their body in try/catch that catches `ApiException` and surfaces errors via `ScaffoldMessenger.of(context).showSnackBar` with `AppColors.danger`, while success feedback uses `AppColors.success` snackbar messages.
- Modal interactions (directions, contact host, cancel confirmation) are exposed as private methods (`_showDirections`, `_showContactHost`, `_showCancelDialog`) invoked from the primary CTA or overflow menu, keeping navigation logic out of the widget tree.
- Status-driven UI branches on `BookingStatus` (confirmed/pending/completed/cancelled/noShow/refunded) plus the special `isAwaitingPayment` flag to render distinct colors, icons, labels, and action sets per booking state.
