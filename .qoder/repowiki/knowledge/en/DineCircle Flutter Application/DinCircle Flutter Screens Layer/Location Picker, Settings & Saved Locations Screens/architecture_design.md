Three sibling ConsumerStatefulWidget screens under `lib/screens/location/`, each owning its own UI state while delegating persistence to Riverpod providers in `../../providers/`:
- `location_screen.dart` — the primary picker: reads supported cities from `supportedCitiesProvider`, uses `geolocator` + `geocoding` for Current Location reverse-geocoding, shows Home/Work quick-jump tiles, filters by search query, and commits via `lastSelectedCityProvider` / `lastSelectedAreaProvider` plus an `onLocationConfirmed` callback.
- `location_settings_screen.dart` — account-level settings screen that calls `sessionControllerProvider.notifier.updateSettings({'city', 'homeArea'})` and surfaces errors via `ApiException`.
- `saved_locations_screen.dart` — CRUD surface over `savedLocationsProvider`: pinned Home/Work tiles, favourite/custom lists with swipe-to-delete (`Dismissible`), and an `_AddLocationSheet` bottom sheet that creates local-only `SavedLocation` entries (id prefixed `local_`) for optimistic sync.

Internal layering is flat: widgets are defined inline as private classes (`_QuickActionTile`, `_CityAreaCard`, `_PinnedLocationTile`, `_SavedLocationRow`, `_AddLocationSheet`) rather than split into separate files. Cross-cutting concerns (theme tokens, spacing, text styles) come from `../../theme/`; reusable buttons/chips from `../../widgets/`. Dependency direction is one-way: screens → providers/models/widgets/theme; no cross-imports between the three screen files.
