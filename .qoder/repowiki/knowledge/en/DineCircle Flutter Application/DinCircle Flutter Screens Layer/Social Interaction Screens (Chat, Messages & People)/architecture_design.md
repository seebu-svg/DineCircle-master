Three sibling screen files, each a self-contained Flutter widget tree that reads state from Riverpod providers in `../../providers/` and renders via shared widgets (`DataView`, `AvatarWidget`).
- `chat_detail/chat_detail_screen.dart`: `ConsumerStatefulWidget` displaying a single event group thread. Messages are fetched through `chatThreadProvider(id)` which REST-polls every 5s; sending posts to `POST /events/:id/messages` and clears the composer immediately. Long-press on another user's message opens a bottom sheet with report/block actions wired to `ReportSheet.show` and `confirmAndBlock` from `screens/safety/`. The host-only menu item is gated by comparing `dinner.host.id` against `currentUserIdProvider`.
- `messages/messages_screen.dart`: `ConsumerWidget` listing all dinners the signed-in user participates in via `chatConversationsProvider`; tapping navigates into `ChatDetailScreen` through an injected `onConversationTap` callback.
- `people/people_screen.dart`: `ConsumerStatefulWidget` with a `DefaultTabController` (Discover / Followers / Following). Discover uses `userDiscoverProvider(PeopleSearch(query))` with a 500ms debounce over a `TextField`; Followers/Following use `followersProvider`/`followingProvider` keyed by `PeopleSearch(userId: me)`. Each row is an `_PersonCard` with optimistic follow/unfollow toggling via `socialControllerProvider`, rolling back on failure and re-syncing through provider invalidation.
Dependency direction is one-way: screens → providers/models/widgets/theme; no cross-imports between the three screen directories.
