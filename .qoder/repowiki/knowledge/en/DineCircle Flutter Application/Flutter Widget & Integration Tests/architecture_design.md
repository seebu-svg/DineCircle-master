Tests are organized as a flat collection of `*_test.dart` files under `test/`, each targeting one screen or feature (auth, bookings, host dashboard, settings, QR code, social wiring, session controller). Shared infrastructure lives in two sibling files:
- `support/overflow_harness.dart` — reusable helpers (`startOverflowCapture`, `applyViewport`, `applyLandscapeViewport`, `applyTextScale`, `applyKeyboardInset`, `themedApp`) that wrap widgets in `ProviderScope` + `MaterialApp(theme: AppTheme.darkTheme)` and treat any `RenderFlex overflowed` message as a test failure.
- `fake_repositories.dart` — a single large file containing fixture constructors (`fixtureRestaurant`, `fixtureDinner`, `fixtureBooking`, `fixtureReview`, `fixtureOffer`, `fixtureInvite`) and fake implementations of every app repository (`FakeEventsRepository`, `FakeRestaurantsRepository`, `FakeUsersRepository`, `FakeBookingsRepository`, `FakeSocialRepository`, `FakeChatRepository`, `FakeOffersRepository`, `FakeSessionRepository`, plus `InMemorySecureStorage`). Each fake exposes call counters and last-invocation fields so tests can assert side effects.

Dependency direction is one-way: tests import production `screens/*`, `providers/*`, and `models/*`; they never import each other except through the shared fakes. The overflow audit (`layout_overflow_test.dart`, `layout_overflow_extended_test.dart`, `layout_overflow_components_test.dart`, `layout_overflow_sheets_test.dart`) runs a Cartesian matrix over widths `[320, 360, 390, 430, 600]` × text scales `[1.0, 1.3, 2.0]` per screen, failing on any captured overflow. Workflow tests like `booking_flow_test.dart` walk multi-step user journeys (Seats → Guest Info → Review → Pay) using the same fake-backed provider overrides.
