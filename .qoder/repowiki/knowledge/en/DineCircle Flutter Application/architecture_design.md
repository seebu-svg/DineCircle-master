The root is a single Flutter app whose entry point (`lib/main.dart`) wraps `MaterialApp` in a `ProviderScope` and drives a session-gated flow: splash → onboarding/auth → preferences → `AppShell`. Cross-cutting concerns live outside the child scopes: `lib/theme/` supplies the dark theme consumed by both screens and widgets; `lib/providers/` (Riverpod) is the single source of state that screens read and widgets render; `lib/services/`, `lib/repositories/`, `lib/models/`, and `lib/api/` form the data layer behind providers. The `server/` directory is an independent Node.js/TypeScript Express API (with its own Dockerfile, docker-compose, schema.sql, and integration tests) that the Flutter client calls via Dio — there is no shared code between the two halves, only HTTP contracts. Android (`android/`) and iOS (`ios/`) are standard Flutter platform wrappers, while `web/` provides PWA assets. Tests under `test/` drive screens and flows using fakes from `fake_repositories.dart` and an overflow-harness harness.
