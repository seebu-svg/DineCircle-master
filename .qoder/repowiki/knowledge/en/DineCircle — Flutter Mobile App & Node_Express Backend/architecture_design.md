Two independent sub-projects share one repo:

- `lib/` is the Flutter client (SDK ^3.13.4). Entry point `lib/main.dart` wraps the tree in `ProviderScope` and drives a session-gated flow: splash → onboarding/auth → preferences → `AppShell`. `app_shell.dart` renders the 5-tab IndexedStack (Home / Explore / Create / Bookings / Profile) and delegates deep navigation to per-screen widgets under `screens/`, state via `flutter_riverpod` providers (`providers/`), data models under `models/`, HTTP through Dio (`api/`), and shared UI under `widgets/` and `theme/`. Platform shells live in `android/` (Kotlin MainActivity, Gradle Kotlin DSL) and `ios/` (Swift Runner, Xcode workspace).
- `server/` is a Node ESM TypeScript Express 5 API. `src/server.ts` wires helmet, cors, rate limiters, a Stripe webhook mounted before JSON parsing, then mounts ~20 route modules under `/api/*` and `/api/partner/*`. Authenticated routes go through `requireAuth` + `auditLog`; WebSocket connections are handled by Socket.io on the same HTTP server, re-verifying event/restaurant membership per message. Shared cross-cutting code lives in `src/context.ts`, `src/security.ts`, `src/db.ts` (pg pool), `src/schema.ts` (SQL schema generator), `src/payments.ts` (Stripe init), `src/reservations.ts`, `src/pricing.ts`, `src/access.ts`.
- `supabase/config.toml` declares the Supabase project; `server/database/security_hardening.sql` and `server/src/schema.sql` define the Postgres schema used by both sides.
- Test suites: Flutter tests under `test/` (with `support/overflow_harness.dart`); server integration/unit tests under `server/src/tests/*.integration.test.ts` and `database_config.test.ts`.
